## 2026-11-03 — Checkpoint 11D-1: Portable authenticated recovery prototype

## 2026-11-03 — Checkpoint 11D-3: Opt-in encrypted checkpoint-on-write
- **Implemented:** `SealedMemorySession(checkpoint_dir=existing_directory)` automatically serializes its complete in-RAM SQLite image and publishes a **new** Windows DPAPI-encrypted snapshot following each successful public `add` or `put_decision` mutation. No plaintext SQLite file is intentionally written.
- **Immutability:** checkpoint filenames use random UUIDs, no old files are overwritten, removed or rotated. `last_checkpoint` identifies the last successful automatic snapshot only.
- **Failure reporting:** if encrypted publication fails after a committed in-memory write, the write call raises, the RAM session remains modified and `has_unsaved_changes=True`, while the last successful encrypted snapshot remains unchanged. A caller must avoid blind retries because the original mutation already happened in RAM.
- **Resource/operational trade-off:** a full-image DPAPI encryption and file is produced on every write. This is much more I/O, CPU and disk use than batch saving, and can quickly fill a disk. The 1 MiB image cap still applies; no pruning/retention policy yet. Existing optional manual save mode remains unchanged.
- **Tests added:** six Windows-native scenarios for reopening from last checkpoint, decision revision chain, simulated disk-full after mutation, invalid write, resuming from checkpoint, and invalid directory. [GitHub Actions #41630117495](https://github.com/naraya07pedro-spec/VARYN/actions/runs/41630117495) passed **135 discovered tests per OS** (129 previous + 6 new), performance benchmark and CLI checks, on Windows and Ubuntu at tested code commit `54f23cd92b24de1ee373970237576aa6b9280999`. Windows-native checkpoint tests passed; Ubuntu skipped them as intended.
- **Safety limits:** simulation is NOT actual power-loss testing. Windows filesystem data/metadata durability across sudden power loss and SSD cache behavior are not guaranteed by these tests; there is no directory fsync, concurrency coordination, automatic rollover, or crash injection process termination. If power fails between mutation and durable snapshot publication, latest edits can still be lost. No real sensitive data.

## 2026-11-03 — Checkpoint 12C: In-process request and output-token budget
- **Implemented:** `varyn/usage_budget.py` with `UsageBudget` and `BudgetedRouter`. Each explicitly selected provider call reserves one request slot and its maximum permitted output tokens *before* dispatch. Lock-protected counters prevent competing threads from overcommitting the same in-memory budget.
- **Failure policy:** once reserved, unsuccessful or uncertain calls keep their reservation rather than falsely assuming the provider did not bill. No automatic retry or fallback.

Provider usage may include input tokens, hidden processing, minimum charges or ambiguous failed requests. The budget is memory-only, resets on restart, is per-process and can be bypassed by calling a raw provider or router directly. Real API calls have not been tested.

## 2026-11-03 — Checkpoint 14A: Bounded synthetic Agent Runtime
- **Implemented:** `varyn/agent_runtime.py` with `BoundedAgent`, `AgentProposal`, and `AgentResult`. Proposals are treated as untrusted, strictly schema-checked JSON with fixed registered tool names. The only available tools are read-only `inspect_status` and mutating `stage_note` which writes synthetic notes to process RAM.
- **Human-in-the-loop simulation:** the mutation path requires `approve(proposal_id)` to issue a one-time opaque token and `execute(proposal_id, approval_token=...)`; rejected or consumed proposals cannot be reused. This is a control-flow prototype, **not production authorization**.
- **Bounds:** configured step count, pending proposal count and synthetic note count limits; argument size max 2048 encoded bytes; per-note max 200 characters. Pending proposals count toward available step capacity. Lock protects concurrent execution and prevents double-dispatch of the same proposal. Dispatched failed steps still consume quota.

- **Safety:** no shell, filesystem mutation, network, browser, external service, model planning, arbitrary tool registration or background autonomy. No agent execution from live model outputs or desktop UI at this checkpoint. All fixtures synthetic.
