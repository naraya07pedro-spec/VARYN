# 17S-40 | Model Control Center: native Windows Tk owner consent and bounded routing

Date: 2026-11-05. This is a **real desktop feature**, not only architectural notes. It builds upon 17S-39 `varyn/model_registry.py`, `varyn/gateway_chat.py`, `varyn/universal_gateway.py` without claiming any official consumer-app history synchronization.

## Visible controls

The main VARYN Tk window now has **`17S-40 | Open Model Control Center (owner opt-in)`**. The dedicated scrollable window supports:
- Register up to twelve **RAM-only** candidate offers across offline `fake`, OpenRouter, DeepSeek and local loopback-only 9Router. Owner types exact provider model ID, **input and output USD per million tokens**, quote date, and separately checks **I checked prices** and **I reviewed fixed local route**. No catalogue is silently fetched. Dates and rate types are validated, fractional USD precision cannot silently round, duplicate/stale/unreviewed price candidates fail closed. A `route_fixed` checkbox says only what the owner claims about the **selected VARYN entry**: upstream 9Router routing is NOT proved fixed.
- Select `auto` (cheapest eligible with a reviewed fresh quote), or one explicit provider/model. Owner enters estimated input tokens, maximum output tokens and **maximum estimated USD**. `Preview cheapest eligible route (NO network)` produces a local cost estimate without contacting any model, reading secrets, or reserving quota. This does **not** enforce the actual provider invoice.
- Type a bounded **`SYNTHETIC:` fictional** test request, then click **`Review exact request & send ONCE`**. A scrollable native modal exposes exact task, model/provider, dated user-supplied pricing and cost estimate with warnings and a SHA256 review digest. Declining does not reserve budget or send. After approval, the app checks that the selected offers, text, input/output limits, ceiling, network flag and 9Router upstream flag have **not changed** in the reentrant dialog. Only then does it create one `UniversalGateway` request. **No automatic retry or failover**; uncertainty retains an in-memory token/request reservation.
- Every window starts with live-network and upstream authorization **OFF**, regardless of prior selection; they reset OFF after dispatch. For real OpenRouter/DeepSeek, a separate opt-in in the window and the owner's **OS environment** credential are required. For local 9Router, the operator separately attests upstream account authorization; it may independently reroute models or consume provider subscriptions.
- The existing `DesktopController` is left unmodified for portable: older model API controls remain **offline** in `VARYN-Portable.exe`; only the new strictly reviewed gateway obtains optional live capability when the EXE is normally launched (never in `--smoke-only`). There is no login/browser credential scraping, direct native app history reading, model key editor, context upload, external website open, or consumer-app sync.
- One RAM-only `UsageBudget` is reused across reopening the Model Control Center during the same VARYN process. This is NOT durable billing enforcement. Owner closes to discard RAM quotes and output. A request already sent cannot be recalled by closing the window.
- Actual model dispatch uses a worker with **no references to live Tk widgets**; results return through an in-memory queue polled on the Tk main thread. GUI uses a scrollable canvas for low-resolution Windows laptops.

## Security and test gates
`tests/test_model_control_center.py` validates exact USD-to-micro conversion without float rounding, date freshness, explicit quote/route booleans and strict exact review text with native sync/billing flags FALSE.

`tests/test_model_control_center_tk.py` (Windows hosted native Tk) uses actual widgets to test default OFF, rejected quote, approved offline FAKE selection and per-request modal denial, successful no-provider fake response, persistent same-process in-memory quotas across window reopen, and separate live-capability mock DeepSeek response requiring fresh network flag, exact owner review, mock env secret, one dispatch only, and no secret in payload. A legacy offline-only controller refuses live API even if the window checkbox is set.

`varyn/portable_entry.py --smoke-only` was expanded to construct and inspect the new real Tk Model Control Center within an actual frozen Windows EXE, confirm the synthetic quote list and network checkbox start empty/OFF, and close without provider calls. Frozen portable smoke **is not** a real live provider or owner-PC integration test.

## Limitations (do not overstate)
Prices are self-reported operator snapshots; no authoritative provider price feed, rate-limit feed, spending ledger, real-time billing evidence, 9Router internal upstream verification, or model capability scoring. `fake` is synthetic and never contacts a model. Network requests in CI use a controlled mock response, not the owner's real credentials, account or provider endpoint. No real user-device acceptance. A live failure can still be billed. OS/environment credentials may be accessible to other processes under the same Windows account, and this prototype is not a production secret vault. Use fictional text only. Original Option C native official ChatGPT/Claude/Gemini bidirectional memory/history synchronization remains **BLOCKED**, distinct from a model API call.

PR #1 must remain OPEN/DRAFT, `main` unchanged. Exact-commit Ubuntu/Windows regression, hosted native Tk acceptance and frozen portable artifact must pass before the code gate is green.
